# 0x46c300 AI_SetUnitState(UNIT* u, int state, int f3c, a, b, x, y)

[O] Sets an AI unit's intent state and issues the matching order through 0x423710.
1. If u.state (+0x38) == 6 -> return (state 6 = locked, never reassigned).
2. If the unit's owner (ENT[u.ent_id].owner) <= H (human player) -> return. So this only ever commands AI-owned units.
3. u.state = state; u.f3c (+0x3c) = f3c arg; u.f5c (+0x5c) = 0.
4. Map AI state -> order command cmd for 0x423710(u.ent_id, cmd, a, b, x, y):
| state | cmd | meaning [I] |
|---|---|---|
| 0 | 7 | idle/stop |
| 1, 4 | 2 | (cmd 2 = ?; used with value arg in tick case 7, perhaps guard/follow) |
| 2 | 7 if x==-1 && y==-1 else 1 | 2 = sent to a guard point: no target -> stop, else move/attack-move to (x,y) |
| 3, 5 | 1 | cmd 1 = go to (x,y) |
Callers: 0x46bec0 loop B (state 3 queued order: args from u+0x4c..0x5a; otherwise state 2 with all -1), more unread.
Resolves: AI state values seen in 0x46b260: 0 idle, 2 assigned/moving to guard point, 3 queued order, 6 locked. cmd 7 appears to be "stop/hold".
