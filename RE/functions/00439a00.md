[O] Time-sliced A*-style search on the 128x128 tile grid, 8 neighbours (dx table 0x4b66e0, dy 0x4b6700, stride 4). pathState (short[]) lives in ENT at +0xd4: [0] state, [1] slot idx (=ent+0xd6), [2] busy, [3,4] start tile x,y, [5,6] goal tile x,y, [7,8] cur, [0x13+i] waypoint x tiles, [0x13f+i] waypoint y tiles (= ent +0xfa/+0x352 arrays), [0x26b] count. Max waypoints 0x12b.
STATES: 1 init (alloc slot: first buffer in 0x6e75c0 + n*0x2ef4 whose count==-1; none -> state 0 retry later), 2 searching, 0x29a reconstruct, 3 DONE (waypoints reversed into forward order, slot freed), 9999 FAIL (slot freed).
SLOT BUFFER (0x2ef4 B): +0 open/closed node count (short), +2.. nodes packed (y<<8|x) (max 0x5d3 =1491), f-values int[] @0x6e817c, g-costs short[] @0x6e98ec, cursor x@0x6ea4a4 y@0x6ea4a6 f@0x6ea4a8 g@0x6ea4ac.
SEARCH per call: up to 15 expansions. Expand cursor: for each of 8 neighbours inside map: BLOCKED if terrain class 0x8352f0[tile]!=1 (unless tile belongs to the unit's own target building footprint), or occupied 0x6d3920 by another unit (ignored if that unit is self / its target; ignored if mover is a non-building-class unit [UnitType+0x24 field 0x4c0874==0? i.e. mobile] and occupant is a building-class; occupants that are moving (+0x6c/+0x70 !=0) or in state 5 are ignored => units path through moving friends), mine terrain tiles 0x3e5/0x3e6 passable only for their owner. New node: g=cur.g+1, f = octagonal dist to goal (max+min/4) [greedy-best-first/A* with unit step cost]. For units with order mode (+0x7e) 6 or 9 (flee/avoid) adds enemy-influence cost map 0x78fde0 (+ player*0x2000 per other player 1..6) to g and 4x to f. Then picks open node with min f (closed marked f=0x753a) as new cursor.
Early exits: cursor==goal -> 0x29a; mode(+0x74)==2 (approach/attack) and dist(cursor px,goal px) < weapon range (+0xa2) (minus half building size if target building) -> goal := cursor, 0x29a; node list overflow (>0x5d3) -> pick lowest-f node as goal ('closest reachable'), 0x29a; no open nodes -> 9999. Invalid target ent/bldg (dead) -> state 0 and ent+0x72=0. Goal tile (ent+0x50/52) not class 1 -> abort.
RECONSTRUCT (0x29a): from goal walk back choosing the neighbour in the node list with smallest g until reaching start (ent+0x6/8 = param[3],[4]); append waypoints (param_1[2]=1 = path valid), reverse array, state 3.
Notes: greedy f (no g in f) => NOT optimal, fast; paths can be odd. Deterministic (no RNG).

## rev 2 — VERIFIED bit-exact (3000 random scenarios on real maps; real x86 code run natively vs C port src/path/path_ref.c, full memory image hashed after every call)
Corrections to the text above:
- Grid index = x*128+y (x = first coordinate; dx table 0x4b66e0 = {0,1,0,-1,-1,1,1,-1}, dy 0x4b6700 = {-1,0,1,0,-1,-1,1,1}, stride 4, 8 entries). Pixel->tile = >>5.
- MINES: tile art 0x3e5/0x3e6 with (ownerMap 0x8464f0 & 0xf) == mover owner => BLOCKED for the owner (own mines avoided); other players' mines are NOT avoided.
- Occupancy 0x6d3920 byte = ent idx+1. Ignored (passable) if: self; the mover's target ent; (mover owner != occ owner && TypeFlag[mover type]!=0 && TypeFlag[occ type]==0), TypeFlag = short @0x4c0874+type*0x4c; occupant moving (ints at occ+0x2c/+0x30 != 0); occupant order-state(+0x62)==5.
- Offsets below are relative to ENT base 0x67fe10 as used by THIS routine's absolute addresses: owner +0, type +2, alive +0xc, goal px x/y +0x40/+0x42, target bldg +0x46, target ent +0x48, order state +0x62 (cleared on abort), mode +0x64 (2=approach), flee mode +0x6e (6/9), range +0x92, pathstate +0xd4, +0x5e4 cleared on init. [?] the older text/structs.md use offsets 0x10 higher for some of these (e.g. 0x56/0x58/0xa2); reconcile in structs.md.
- Building (base 0x805df0, stride 0xe0): +0 and +8 nonzero = alive; footprint x0 +0x18, y0 +0x1c, w +0x20, h +0x24 (ints). Footprint tiles forced passable for a mover targeting it. Range-exit subtracts (w+h)/4 px-units.
- 13 slots (0x6e75c0 + n*0x2ef4), free = count word == -1. Count word = index of LAST node (entries 0..count). Start node is never marked closed (f stays h). Closed f = 0x753a. Node cap check `count > 0x5d3`; overflow picks min f over idx 0..count-1 (closed 0x753a < 0x7544 count too).
- No decrease-key: a neighbour already in the node list (open or closed) is skipped. g = parent g + 1 (16-bit); flee adds infl map (0x78fde0 + p*0x2000, 64x64 shorts, index (x>>1)*64+(y>>1)) to g and 4x to f, for p=1..6 != owner.
- Reconstruct walks from goal choosing neighbour node with min g (first in dx/dy order on ties), cap 299 waypoints, then reverses.
- Known weaknesses (fix targets): f = h only (greedy), no re-open, 15 expansions/call, 1491-node cap -> "closest" fallback on big maps, path through moving units, occupancy snapshot at plan time.
